# Обработчик MAX для VPS

Node.js 24, без внешних пакетов. Принимает события MAX по `/webhooks/max` и заявки сайта по `/api/leads`, передаёт их в существующий сервис Sites. Заявки, получатели, проверка пароля и отправка ответов остаются в Sites. `/health` сообщает о работе процесса, но сам по себе не подтверждает доставку событий или заявок.

Процесс слушает только `127.0.0.1:8789`. Снаружи нужен отдельный HTTPS virtual host reverse proxy с действующим сертификатом и ограничением тела запроса 16 КБ. Не заменяйте настройки существующих сайтов на VPS. Сначала проверьте свободные порты и действующий reverse proxy, затем добавьте отдельный host. Образец systemd unit требует пользователя `prioritet-max`; путь к Node.js нужно сверить на сервере.

`MAX_WEBHOOK_SECRET` в `/etc/prioritet-max.env` должен совпадать с секретом в Sites и в регистрации MAX. Файл хранится только на сервере с правами `0600`, исходники не содержат его значения. Токен MAX, пароль подписки и данные пользователей этому обработчику не нужны. Тела событий, заголовки и секреты не записываются в журнал.

Для заявок задайте отдельный `LEAD_PROXY_SECRET` в этом же файле и в Sites, а также `ALLOWED_ORIGINS` — точный список HTTPS источников через запятую. Публичный адрес задаётся в `src/lib/public-gateway.js`; необязательный `PUBLIC_LEAD_API_URL` не должен указывать браузер напрямую на Sites, если тот недоступен в регионе клиента. CORS проверяется и на VPS, и в Sites. nginx в `location = /api/leads` обязан заменять `X-Real-IP` значением `$remote_addr`. Обработчик передаёт этот адрес и серверный секрет в Sites, чтобы ограничение частоты работало отдельно для посетителей. Неподписанные и поддельные заголовки в Sites не меняют клиентский адрес.

Видеофайл публикуется nginx отдельным точным маршрутом `/media/atelier-introduction.mp4`, с поддержкой Range и без изменения исходного ролика. Не выставляйте каталог сервера целиком. При обновлении сверяйте SHA256 файла с `public/assets/marketing/atelier-introduction.mp4`.

После запуска проверьте `/health`, отказ без правильного секрета, обработку подписанного неизвестного события без создания заявки и передачу ошибок сервиса. Затем обновите `MAX_WEBHOOK_URL` в Sites, примените окружение публикацией существующей версии и зарегистрируйте HTTPS URL через официальный API MAX. Для обращения к `platform-api2.max.ru` проверяйте TLS с официальными сертификатами Минцифры в отдельном клиенте; не отключайте проверку сертификатов и не меняйте системное хранилище доверия.

Окончательная проверка — реальная команда `/start`, ввод пароля пользователем, активная подписка в закрытой базе и ответ на `/status` без локального опроса API. Для проверки доставки заявок используйте согласованный с владельцем тест. Временный long polling не является постоянным решением.

Локальные проверки: `node --test tests/max-relay.test.mjs` из корня сайта.
